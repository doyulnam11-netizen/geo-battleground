# 실제 검증 기록

검사 환경: Linux, Node 24.19, Chromium headless + SwiftShader(WebGL 소프트웨어 렌더링). Windows/Android/iOS 기기를 직접 연결한 검사는 수행하지 않았습니다. 이 문서는 실제 실행 결과와 미검증 항목을 구분합니다.

## 자동 검사

`npm test`: **32/32 통과 (2026-10-27)**.

- 문제은행: 100문항, ID·질문 중복 없음, 4지선다, 정답 인덱스, 40/40/20 난이도, 18개 주제.
- 로비: 방장 권한, 준비 상태, 12명 상한, 다른 스폰 위치.
- 퀴즈: 첫 기절, 정답 숨김, 25초/정확한 경계시각, HP35, 보호3초, 두 번째 기절 탈락, 중복/잘못된 입력 무시.
- 동시 기절의 독립 질문, 퀴즈 중 추가 피해·이동·회복 잠금, 재연결 후 문제/마감시각/기회 유지, 연결 종료 중에도 시간초과 처리.
- 안전구역 공통 스냅샷/축소/구역 밖 피해, 아이템 원자 획득/거리, 치료 시간·취소·수량, 재장전·연사 간격.
- 입력 정규화/큐 상한/HP·좌표 주입 무시, 벽·암석 충돌/사선 차단, 점프·중력·자세 높이.
- 서버 실명중/부위 피해, 순위·승리·로비 복귀·새 라운드 기회 초기화, 연습 명령 온라인 차단.
- 내보낸 GLB가 17본과 유효한 18개 애니메이션을 포함하는지 검사.
- 전망대 계단을 갑작스러운 큰 수직 이동 없이 올라가는지 검사. 최초 상판 간섭 실패를 발견해 상판 위치를 수정한 뒤 통과했습니다.

위 검사 중 `tests/network.test.ts`의 2개는 실제로 열린 HTTP/WS 서버와 별도의 TCP WebSocket 연결을 사용합니다. 가짜 소켓 객체로 대체하지 않았습니다. 같은 방 입장, 준비/시작, 다른 클라이언트에서 이동 ACK 확인, 서버 퀴즈 출제, 소켓 종료/토큰 재접속, 정답 부활/최종 탈락/공통 승리 상태와 잘못된 토큰 거부를 확인했습니다. 네트워크 테스트의 치명 피해 배치는 테스트 프로세스 내부에서 수행하며, 제품에는 관리자 피해 명령이나 테스트용 HTTP 경로가 없습니다.

`npm run build`: **통과**. TypeScript noEmit 검사, Vite 정적 빌드, esbuild Node 서버 번들 생성. 온라인 100문항 JSON은 서버 번들에 있고, 클라이언트의 연습 Worker는 별도 8문항만 포함합니다.

## 브라우저 검사

초기 수동/자동 실행에서 다음을 확인했습니다.

- 실제 WebGL 장면이 있는 데스크톱 메뉴 렌더링 및 JS 런타임 오류 없음.
- 도감의 시대 전환.
- 연습 모드의 실제 전투 중 기절 및 퀴즈 표시.
- 연습 메뉴로 기절을 유발한 후 정답 선택 → HP 35 표시.

동일 SwiftShader GPU 프로세스에서 두 Chromium 컨텍스트를 동시에 초기화하는 검사에서는 두 번째 화면 로드가 시간초과했습니다. 이를 실제 2기기 브라우저 통과로 기록하지 않습니다. 별도 프로세스/실제 GPU 및 실제 기기 검증이 필요합니다. `QA_CONCURRENT_BROWSER=1 npm run test:browser`로 재시도할 수 있습니다. 기본 브라우저 스크립트는 단일 컨텍스트씩 검사하고, 2개 동시 컨텍스트 항목은 미검증으로 기록합니다.

최종 순차 브라우저 검사: **7개 통과, 동시 브라우저 1개 미검증**. `docs/browser-results.json`에 실제 결과를 보존했습니다. 844×390 터치 에뮬레이션에서 세 개의 실제 CDP 터치 포인터를 동시에 보내 이동·시점·발사와 탄약 감소를 확인했습니다. 390×844 세로 회전 안내, 1180×820 태블릿 전용 조이스틱 크기도 통과했습니다. 최종 검사에서 JavaScript 런타임 오류는 없었습니다.

## 수행하지 않은 검사

실제 Android/iPhone/iPad/Windows, Safari/WebKit, 12명 실기기 부하, 실제 WAN 지연/손실/재접속 장기 반복, 모바일 GPU 온도·배터리·FPS, Docker 이미지 빌드/컨테이너 실행, 사용자 도메인 운용, 교육 전문가의 교과서 대조. 목표 FPS를 달성했다고 표시하지 않습니다. SwiftShader FPS는 모바일/PC GPU 성능을 대표하지 않습니다.


## 추가 기능 검사 — 2026-10-27

- 기울이기: 부드러운 카메라/몸체 이동, 벽 앞 머리 스윕, 질주/엎드리기 제한, 입력 범위 제한, 서버 스냅샷 동기화, 기절 시 초기화, 기울인 발사 원점과 대상 머리 피해 판정을 검사했습니다.
- 패킷 간격: 입력 지연 시 이동/발사는 멈추되 기울인 자세는 유지하며, 명시적 해제 입력이 중앙 자세로 돌려놓는지 확인했습니다. 렌더링과 입력 타이머를 분리했습니다.
- 회복 아이템: 각 스폰 주변 실제 med/kit 생성, 벽 너머 획득 방지, 가장 가까운 아이템 우선 획득을 검사했습니다.
- 브라우저 추가 검사: **3개 통과**. 버튼별 크기·불투명도·드래그 위치의 새로고침 후 유지, 네 개 동시 CDP 터치로 이동/시점/발사/기울이기와 해제, 높은 품질의 PBR/SSAO 렌더링을 확인했습니다. JS 및 WebGL 셰이더 오류가 없었습니다. 보고서는 docs/upgrade-results.json입니다.
- 검사 중 발견한 저프레임 기울이기 해제 문제를 수정한 뒤 재실행했습니다. 첫 설정 저장 검사는 QA 초기화 코드가 매 새로고침마다 저장값을 덮어써 실패했고, 초기화 조건을 수정해 실제 보존 여부를 확인했습니다.
- Render Blueprint는 현재 공식 JSON Schema로 검증했습니다. Render CLI가 설치되어 있지 않아 플랫폼 측 CLI 검증은 수행하지 않았습니다. 실제 Render 빌드는 아래 공개 배포 검사에서 확인했습니다.
- 실제 Android/iPhone/iPad/Windows 장치는 여전히 미검증입니다. 공개 WSS 서버는 아래 항목에서 별도로 검증했습니다.
- 추가 기능 반영 후 기존 순차 브라우저 검사도 재실행하여 7개가 통과했습니다. 별도의 프로덕션 번들을 PORT=3099에서 실행해 HTTP 화면/상태 확인 및 독립된 두 WebSocket 간 기울이기 전달을 확인했습니다. 이는 로컬 실행 검증이며 공개 Render 배포 검증이 아닙니다.

## 공개 Render 서버 검사 — 2026-10-27

- 싱가포르 무료 Node 서비스의 실제 배포가 LIVE 상태가 된 것을 확인했습니다. Render에서 의존성 설치·테스트·프론트엔드와 서버 빌드가 성공했습니다.
- https://geo-battleground.onrender.com/api/health 의 HTTPS 응답과 공개 WSS 경로를 확인했습니다.
- 독립된 두 WSS 클라이언트로 6자리 방 생성/참가, 준비/공통 시작시각, 공통 안전구역, 상대 이동·기울이기·발사/탄약, HP 주입 무시, 끊긴 연결의 동일 플레이어/방 복원을 확인했습니다.
- 기록: [public-network-results.json](public-network-results.json). 세션 프록시를 통한 실제 외부 TLS 연결이며, 실제 휴대폰 두 대를 사용한 검사는 아닙니다. 공개 서버에서 치명 피해/퀴즈 전체 경기를 자동 시험한 것은 아닙니다. 퀴즈의 서버·로컬 소켓 검사는 앞 항목에 별도로 기록했습니다.
- 별도 정적 호스팅에서 서버 상태를 읽기 위한 공개 CORS 응답과 비밀값 비노출 검사를 추가했습니다. 이에 따라 자동 검사 합계는 32개입니다.
