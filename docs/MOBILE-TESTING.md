# 모바일·태블릿 실기기 검사 가이드

자동 검사는 Linux Chromium의 터치/뷰포트 에뮬레이션입니다. Android OS·iOS WebKit·실제 모바일 GPU·발열·오디오 지연을 검증한 결과가 아닙니다.

## 기기별 수행

- Android Chrome: 보급형 1대와 중급형 이상 1대, 844×390 전후 CSS 가로 화면.
- Android 태블릿 Chrome: 1180×820 전후 가로 화면.
- iPhone Safari: 노치/홈 인디케이터를 포함한 가로 안전영역.
- iPad Safari: iPadOS의 데스크톱 사이트 설정, 외부 키보드 연결/해제.
- Windows Chrome/Edge: 포인터 잠금, 마우스 우클릭, 키 재설정.

실제 HTTPS URL로 접속하고 다른 기기도 같은 서버 주소를 사용합니다. 최소 두 기기로 방 생성·코드 입장·준비·동시 시작을 확인합니다.

## 터치 검사

1. 세로로 열면 가로 회전 안내가 화면을 덮는지 확인합니다.
2. 가로에서 모든 조작 버튼이 보이고 안전영역과 HUD가 겹치지 않는지 확인합니다.
3. 왼손 조이스틱을 유지하며 오른쪽 빈 영역을 드래그합니다. 시점과 위치가 동시에 바뀌어야 합니다.
4. 세 번째 손가락으로 발사를 유지합니다. 이동·시점 변화가 멈추지 않고 탄약이 감소해야 합니다.
5. 네 번째 손가락으로 좌/우 기울이기를 누르고 다른 기기에서 상체와 사선이 기울어지는지 확인합니다. 손을 떼면 돌아와야 하며 벽에 붙어 기울여도 벽 안을 볼 수 없어야 합니다.
6. 조작 설정에서 전체 버튼 크기·불투명도를 변경합니다. 버튼별 편집에서 발사 버튼만 크기 125%, 불투명도 55%로 바꾸고 위치를 옮깁니다. 새로고침 후 유지와 배치 초기화, 가로/세로 회전을 확인합니다. 조준 유지/토글과 감도도 검사합니다.
7. 손가락이 버튼 밖으로 나가거나 OS 알림/다른 앱 전환이 발생할 때 발사가 멈추는지 확인합니다.
8. 키보드 입력 없이 장비 변경, 재장전, 획득, 회복, 지도, 가방을 사용할 수 있어야 합니다.

## 상태 동기화

첫 기절 → 문제 25초 → 정답 HP35/보호3초 → 두 번째 기절 즉시 탈락을 확인합니다. 다른 기기에서는 기절 자세와 복귀를 확인합니다. 별도 라운드에서 오답/시간초과도 확인합니다. 동시에 기절한 두 명은 질문과 마감시각을 독립 유지해야 합니다.

문제 중 Wi-Fi를 5초 끊고 복구하세요. 질문 ID/마감시각/기회 사용 여부가 바뀌면 실패입니다. 같은 탭 새로고침 복구도 검사하세요. 연결이 끊겨도 서버는 시간을 멈추지 않습니다.

## 성능 기록

설정 → 성능 패널을 켜고 각 품질에서 3분 이상 플레이합니다. 기기 모델, OS, 브라우저 버전, DPR, 그래픽 설정, 평균/최저 FPS, 기기 발열, 배터리 상태를 기록하세요. 목표는 스마트폰 30+, 태블릿 45~60, PC60이지만 현재 실기기 측정으로 달성 여부를 검증하지 않았습니다. 자동 해상도 조절이 화질 저하를 동반한다는 점도 기록합니다.

Safari는 Web Audio가 첫 사용자 터치 후 시작되는지, 포인터 이벤트와 기기 회전 시 canvas 크기가 갱신되는지, 탭 백그라운드 복귀 후 WSS 재접속이 되는지 별도로 확인합니다.
