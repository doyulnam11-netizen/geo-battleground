# 설계와 권한 경계

## 스택 선택

React 19는 메뉴·HUD·모달을 담당하며, Three.js 0.180은 독립된 렌더러 클래스에서 WebGL2 장면을 갱신합니다. React Three Fiber/Drei/Zustand는 필수 의존성을 줄이고 30Hz 입력 루프와 렌더 루프를 직접 통제하기 위해 사용하지 않았습니다. 상태 전달은 Connection 인스턴스와 React state로 구성합니다.

Colyseus 대신 ws를 선택했습니다. 방/토큰/스냅샷 프로토콜이 작은 한 서비스 안에 있고 외부 DB 없이 실행 가능합니다. 권한 판정은 모두 GameRoom에 있습니다. 클라이언트가 보내는 메시지에는 HP 변경, 위치 설정, 퀴즈 정답 변경 명령이 없습니다.

Rapier 대신 공유 TypeScript 운동학 충돌기를 사용했습니다. 수평 원형 캡슐 풋프린트와 자세에 따른 높이를 AABB에 검사하고 중력·높이함수 지면·0.42m 계단 오르기를 계산합니다. 서버와 브라우저 예측이 같은 함수를 사용합니다. 이는 일반 강체 물리 엔진이 아니며 경사진 삼각형/복잡한 오목 메시의 정확한 충돌을 대체하지 않습니다. 바위는 보수적인 상자 콜라이더이고 나무는 줄기만 충돌합니다. 고급 물리 품질 요구에는 Rapier로 이전하는 후속 작업이 필요합니다.

## 프로토콜

접속 후 create / join / quick / resume 중 하나를 보냅니다. 첫 접속에는 암호학적으로 생성한 ID와 32바이트 세션 토큰을 반환합니다. 방 코드 6자리는 공개 입장 코드이며 세션 토큰을 대신하지 않습니다. 서버는 메시지 최대 4KB, 초당 입력 제한, 숫자 유효성, 입력 큐 4개 상한, 이동 입력 -1~1 정규화, 서버 tick당 최대 이동을 적용합니다.

30Hz 서버 틱이 입력을 하나씩 처리하고 15Hz로 권한 스냅샷을 보냅니다. ACK 이후 아직 처리되지 않은 입력을 클라이언트가 재실행하여 보정합니다. 상대 캐릭터는 새 스냅샷으로 보간합니다. 180ms 이후 새 입력이 없으면 이동·발사를 멈춥니다. WebSocket의 순서 보장과 재전송을 사용하며 UDP/FEC는 없습니다. 서버의 짧은 위치 이력으로 최대 150ms 범위의 위치를 참고해 명중을 계산합니다. 클라이언트 시각은 이 범위로 제한합니다. 정교한 경쟁전 수준의 지연 악용 방지/서버 측 RTT 추정은 미완료입니다.

명중은 카메라와 같은 각도의 ray를 사용합니다. 서버가 장탄·연사 간격·재장전 시간을 확인하고 지형/엄폐물과 머리·몸통·팔/다리 AABB를 검사합니다. 부위 상자는 실제 리깅된 애니메이션 메시와 정확히 일치하지 않는 근사치입니다. DMR은 새 발사 입력에서만 발사됩니다. 전투는 비잔혹 가상 장비 표현입니다.

## 퀴즈 상태 전이

alive(HP>0) → HP=0 && !reviveUsed → downed + reviveUsed=true + 서버 질문/마감시각 저장.

- 유효 정답 && now < deadline: alive, HP=35, protectedUntil=now+3000.
- 오답 또는 now >= deadline: eliminated.
- reviveUsed 이후 HP=0: 바로 eliminated.
- downed 상태에서는 이동·발사·치료·피해를 처리하지 않음.
- 해결 시 질문 Map에서 먼저 삭제하므로 중복 답안은 무시됨.
- 연결 종료가 상태를 새로 만들지 않으며 같은 토큰으로 같은 플레이어와 마감시각을 복구.
- 문제 선택은 한 라운드의 사용된 ID 집합을 사용해 불필요한 반복을 방지.
- 다운시킨 플레이어는 그 퀴즈가 실패/시간초과해 최종 탈락했을 때 탈락 수를 얻음.

스냅샷의 question에는 정답과 해설이 없습니다. 정답 제출/시간초과 후 해당 플레이어의 quizResult에 정답과 해설을 반환합니다. 온라인 문제은행은 server 번들에만 들어갑니다. 연습 Worker에는 별도로 작성한 8개 연습 문제가 들어가며, 연습 로컬 상태 조작은 온라인 방에 영향을 주지 않습니다.

## 그래픽과 에셋

실시간 높이 메시, 색/노이즈 지면, 반복 가능한 나무·잔디·암석, 실내 출입 가능한 건물, 창문 틈, 계단형 전망대, 암모나이트와 지층 노두를 코드로 생성합니다. 외부 상용 게임 에셋은 사용하지 않습니다. 캐릭터는 17본 SkinnedMesh와 AnimationMixer, 블렌딩 가능한 18개 클립입니다. UI의 배경은 정지 이미지가 아닙니다. GLB는 재사용을 위해 내보낸 동일 모델이며, 런타임은 생성기를 사용합니다.

장비는 실제 3D 프레임/유리/발광 도트를 포함합니다. ADS 전환은 카메라 FOV와 장비 위치를 보간해 조준선에 맞춥니다. 조준 중앙 표시만으로 대체하지 않습니다. 로컬 발사는 서버 승인 이벤트를 받은 뒤 섬광·궤적·반동을 표시합니다. 입력 직후의 사격 애니메이션 예측은 후속 개선 영역입니다.

사운드는 Web Audio 합성으로 만들고 상대 위치에 따른 스테레오 패닝·거리 감쇠를 적용합니다. 실측 HRTF 음원 또는 별도 녹음 파일은 없습니다.

## 운영 한계

프로세스 단위 인메모리 방, 서버 재시작 복구 없음, 100개 방·240개 연결 상한, 다중 인스턴스 방 라우팅/Redis 없음. 여러 프로세스로 늘리려면 방 디렉터리와 고정 라우팅, 외부 저장소, 관찰성 및 부하 검증이 필요합니다. 현재 코드가 대규모 공개 서비스 수준의 부정행위 방지나 DDoS 대응을 완료했다고 주장하지 않습니다.


## 기울이기·회복 아이템·화질 확장

기울이기는 서버가 -1~1 범위로 제한하고 틱마다 보간합니다. 공유 bodyPoint/eyePosition 함수가 실제 발사 원점, 부위별 히트박스 위치와 카메라를 결정합니다. 머리·상체 경로를 스윕하여 엄폐물 내부로 기울일 수 없게 합니다. 상대 리깅 모델 전체에 같은 회전각을 적용합니다. 상자는 여전히 근사 히트박스이며 애니메이션 피부 전체와 일치하는 판정은 아닙니다.

입력 샘플링은 RAF와 분리한 30Hz 타이머입니다. 짧은 패킷 공백에서는 자세를 유지하고, 이동·발사는 기존 180ms 제한을 따릅니다. 연결 종료·기절·탈락 또는 사용자의 해제 입력으로 기울이기를 되돌립니다.

shared/loot.ts를 서버 획득과 UI 안내가 공유합니다. 거리·높이·사선 검사를 통과한 가장 가까운 아이템을 선택하므로 안내와 실제 획득 대상이 일치합니다. 회복 모델은 바닥 높이에 고정하며 회전하거나 떠다니지 않습니다. 재질별 메시 병합으로 세부 부품을 적은 draw call로 표시합니다.

지형·암석·나무껍질 맵은 원본 절차적 색상/노멀/거칠기 텍스처입니다. 높음/매우 높음에 SSAO와 OutputPass를 적용합니다. 자동 품질은 실제 프레임 경과시간으로 성능을 판단하고 느리면 SSAO와 픽셀 비율을 낮춥니다. 휴대폰 GPU 목표 성능은 별도 실기기 검증이 필요합니다.
